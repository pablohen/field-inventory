# Field Inventory: Plan 4, Admin

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The admin area. It covers:
- warehouses, with a Turso database created and migrated automatically
- locations, products, categories with tolerances, and reason codes
- users and roles
- device enrollment and warehouse assignment
- live authorization, so a disabled or demoted user loses access immediately

**Architecture:**
- Admin pages live under `/admin`, use SSR, and are admin-only. They follow the desk patterns from plan 3:
  - each server function has a `handleX(claims, input, deps)` that authorizes first, then calls a core function
  - `*.fn.ts` files contain only `createServerFn` wrappers
  - schemas the client needs live in client-safe `src/admin/*.ts` modules
  - every client call goes through `deskCall`
  - pages follow the R5 polling and error rules
- Authorization moves from "role in the token" to "current user row in the global DB", which closes plan 3's deferred M3.
- Warehouse provisioning sits behind a `WarehouseProvisioner` interface. One implementation calls the Turso Platform API; the file-DB implementation is used in dev and tests.

**Tech Stack:** the existing stack. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-11-field-inventory-design.md` §8 (`/admin` part and Prisma setup), §5.1, §9.1.

**Out of scope:** multi-device Playwright E2E (plan 5); the shared SQLITE_BUSY policy (separate proposed session); reporting.

## Global Constraints

- `/admin` routes and every admin server function are for role `admin` only. Supervisors get 403. Every admin `handleX` calls `authorizeAdmin(claims, global)` first.
- **Live authorization:** every desk and admin handler checks the current global `User` row. It must exist, have `disabledAt === null`, and have the required role in the DB, not just in the token.
- **Login:** a disabled user gets `BAD_CREDENTIALS`, on both the handheld and the desk.
- **Handheld:** a disabled user's handheld session gets 403 on `syncMovements` and `getReplicaConfig`. Push rows recorded by that user before they were disabled are still accepted from other sessions, so no offline work is lost.
- **Warehouse ids:** match `/^[a-z0-9][a-z0-9-]{1,22}$/`. The database name is `fi-<id>`.
- **Where warehouse DBs are created:** Turso, when `WAREHOUSE_DB_URL_TEMPLATE` starts with `libsql://`, via the Platform API with env `TURSO_ORG`, `TURSO_PLATFORM_TOKEN` and `TURSO_GROUP` (default `'default'`). Otherwise a local file DB.
- **Device ids:** match `/^[a-z0-9][a-z0-9-]{1,63}$/`. `desk` and `*` are reserved.
- **PINs:** exactly 4 digits, `/^\d{4}$/` (the handheld `PinInput` has 4 boxes). Stored via `hashPin`.
- **System reason codes** `COUNT_AUTO` and `INITIAL` are read-only in the admin.
- **No hard deletes** of warehouses, locations, products, users or devices, because the ledger references them. Use deactivate, disable or revoke instead.
- Expected failures return typed `DeskError` (`{ ok: false; code; message }`); auth failures throw 401/403.
- Biome is the only linter. Before each commit: `pnpm format && pnpm lint && pnpm typecheck && pnpm test`, plus `pnpm build` and a `dist/client` grep for `PrismaClient`/`@prisma` on tasks that touch routes or `.fn.ts` files.

## Review Focus

1. **Warehouse creation fails partway** (Platform API error, or a migration error after the DB exists). The warehouse shows as "Setup incomplete" with a **Finish setup** action. Retrying is idempotent: an existing DB counts as success, and migrations re-run safely. Test in Task 2.
2. **An admin disables or demotes themselves, or the last active admin.** Refused with `INVALID`, so the system can never be left with no usable admin. Test in Task 5.
3. **A disabled or demoted user still holds a valid 7-day cookie.** The next desk or admin call gets 403 immediately, handheld push and replica config get 403, and sign-in returns `BAD_CREDENTIALS`. Test in Task 1.
4. **A SKU or barcode already belongs to another product.** `INVALID`, naming that product, so a scan can never be ambiguous. Test in Task 4.
5. **A location is deactivated while a pick list is being created, or while a correcting adjustment for it is resolving.** `INVALID` with no partial writes, because the active check is repeated inside the transaction. This closes plan 3's deferred minor. Test in Task 3.

Idempotent. Also serves "Run migrations" for `NEEDS_MIGRATION`.
  - `renameWarehouseCore(deps, id, name)`
